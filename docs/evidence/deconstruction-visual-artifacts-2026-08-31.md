# Visual artifacts in the social story

Implemented and checked locally on 2026-08-31. Not committed, pushed, or deployed.
This extends the [earlier model-written carousel](deconstruction-social-2026-08-31.md).

## What changed

The existing Scribe writer sees the selected Shot, stored observations, and
labelled previews of its available detail crops and Visual Evidence Artifacts.
It can choose one artifact for a story beat that cites the same Technique Evidence.
The exported page pairs the original with that artifact, followed by a factual
legend and the model-written caption. Cover and clean ending remain unmarked.

The same numbered JPEGs serve web and Android. Separate downloads, native sharing,
and the photographer's review and posting control remain unchanged. No extra
agent, new geometry, Analyst rerun, or longitudinal write was added.

The export checks artifact ownership, exact Shot path, source digest, current
renderer, rendered status, and measured or bounded verification. It reads and
hashes the actual file. Missing, unreadable, wrong-framing, stale, rejected,
unresolved, and manual-fixture artifacts do not reach the writer. A subject
contour's measured area must also fit the stored subject's context bounds.
These checks are admission rules, not semantic proof of every visual claim.

The writer's schema limits reference and selection fields to supplied ids.
Gemini receives `none` for an unused visual selection; the adapter maps it to
the existing empty selection after validation. String enums are a documented
structured-output feature. [Google's schema guidance](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/control-generated-output#supported-schema-fields)

## Failures found during implementation

- First attempt: paddy failed after 20.297 s because the writer selected an
  unsupported detail. The exact invalid selection was not captured in that
  first log. An unchanged retry succeeded in 16.078 s, so retry success alone was
  not treated as a fix. Selection diagnostics and schema-bounded choices were
  subsequently added; validation still refuses unsupported or uncited choices.
- First attempt: the moon story rendered in 18.484 s but selected a subject
  contour covering 81.1% of the frame, while the stored subject occupied one
  grid cell. Visual review rejected that page. The export now withholds contours
  that exceed the located subject's context bounds. This is a general consistency
  check, not a filename exception. The source renderer and old Shot-detail
  artifacts were not rewritten or regenerated by this task.
- First attempt: road rendered in 16.437 s with one artifact page. Different
  page selections across model runs are expected; no fixed page recipe is forced.
- Schema iteration: Vertex rejected empty strings in enum fields with HTTP 400,
  `enum[0]: cannot be empty`. The three requests failed in 4.047 s, 2.797 s, and
  2.937 s, with no generation usage receipts. The adapter now uses the explicit
  `none` value. The final real calls exercised the corrected schema.
- No timeout occurred in these checks. Existing SDK/ADK and TestClient
  deprecation warnings remain. Failures were visible; none used template prose
  or a fabricated overlay as a success result.

## Limits and reproducible artifacts

A valid artifact and matching citation do not prove that every sentence is true.
The writer can still misread a Shot. The subject-area check catches a specific
class of contradiction, not all wrong contours or paths. The draft still needs
the photographer's review. No social posting or platform-specific cropping was tested.
